# Cloud Benefits

## Overview

Cloud computing provides several benefits compared with managing all infrastructure and applications on-premises.

For the **AZ-900 exam**, it is important to understand why organizations use cloud services and what advantages the cloud provides.

The main benefits include:

* High availability
* Scalability
* Elasticity
* Reliability
* Predictability
* Security
* Governance and compliance
* Manageability

---

# 1. High Availability

**Availability** means keeping applications and services accessible when users need them.

In the cloud, services can be designed to remain available even when hardware or infrastructure has problems.

### Example I Can Relate To

Imagine I build a **C# ASP.NET Core Web API** and deploy it to Azure.

If the application is running on only one physical server and that server fails, the API could become unavailable.

Azure provides services and configurations that can help keep applications running by using redundant infrastructure.

### Simple Example

```text
User
  ↓
Azure
  ↓
C# ASP.NET Core API
  ↓
SQL Database
```

The goal is to make sure users can continue accessing the application even when individual infrastructure components experience problems.

### Remember

> **Availability = Is the service accessible when I need it?**

---

# 2. Scalability

**Scalability** is the ability of a system to handle an increase in workload by adding resources.

For example, a web application might normally have 1,000 users but later need to support 10,000 users.

### Example I Can Relate To

Suppose I build a **C# + React application**.

Initially:

```text
1,000 users
     ↓
Small amount of compute resources
```

The application becomes popular:

```text
10,000 users
     ↓
More compute resources required
```

Azure allows resources to be increased to support the larger workload.

### Two Types of Scaling

**Vertical scaling**

Increase the power of an existing resource.

```text
Small VM
   ↓
Larger VM
```

For example:

```text
2 CPU / 8 GB RAM
       ↓
4 CPU / 16 GB RAM
```

**Horizontal scaling**

Add more instances of the application.

```text
C# API Instance 1
C# API Instance 2
C# API Instance 3
```

This can allow more users to be handled simultaneously.

### Remember

> **Scalability = Can I increase capacity when demand increases?**

---

# 3. Elasticity

**Elasticity** is the ability to automatically or quickly increase and decrease resources based on demand.

This is slightly different from scalability.

### Example

Imagine a C# web application normally receives:

```text
100 requests/hour
```

During a major promotion:

```text
10,000 requests/hour
```

The cloud can increase resources to handle the additional demand.

When traffic returns to normal:

```text
10,000 requests → 100 requests
```

Resources can be reduced.

### Scalability vs Elasticity

| Concept     | Meaning                                                           |
| ----------- | ----------------------------------------------------------------- |
| Scalability | Ability to increase capacity                                      |
| Elasticity  | Ability to increase **and decrease** capacity according to demand |

### Easy way to remember

> **Scalability = grow**
> **Elasticity = grow and shrink**

---

# 4. Reliability

**Reliability** means a system can perform consistently and recover from failures.

Cloud providers operate large amounts of infrastructure and use redundancy to reduce the impact of failures.

### Example I Can Relate To

If a business application uses:

* C#/.NET API
* Azure services
* SQL database
* Power Automate workflows

the architecture can be designed so that a failure in one component does not necessarily bring down the entire system.

Reliability is particularly important for business applications where downtime can affect users and business processes.

### Remember

> **Reliability = Can the system consistently perform and recover from failures?**

---

# 5. Predictability

Cloud computing can make application performance and costs more predictable when resources are properly planned and monitored.

There are two important areas:

### Performance Predictability

Resources can be selected according to the application's requirements.

For example:

```text
Small application
      ↓
Smaller Azure resources

Large application
      ↓
Larger Azure resources
```

### Cost Predictability

Azure provides tools that allow organizations to estimate and monitor costs.

This is useful because cloud services generally follow a **consumption-based model**.

For example:

```text
More resources used
        ↓
Higher cost

Less resources used
        ↓
Lower cost
```

---

# 6. Security

Cloud providers invest heavily in security infrastructure, tools and services.

However, security is still a **shared responsibility** between the cloud provider and customer.

For example, Azure provides security services such as:

* Microsoft Entra ID
* Azure RBAC
* Microsoft Defender for Cloud
* Azure Key Vault
* Microsoft Sentinel

### Example I Can Relate To

If I deploy a C# API to Azure, I still need to make sure that:

* users have appropriate permissions;
* sensitive information is protected;
* secrets are not stored directly in source code;
* access is controlled;
* application vulnerabilities are addressed.

Azure provides services that can help with these responsibilities.

### Testing Connection

As someone with software testing experience, security is also relevant during testing.

For example:

```text
Application
     ↓
Authentication testing
     ↓
Authorization testing
     ↓
Input validation
     ↓
Access control testing
```

### Remember

> **Azure provides security capabilities, but customers still have security responsibilities.**

---

# 7. Governance and Compliance

Cloud environments provide tools that help organizations control how resources are used.

Examples include:

* Azure Policy
* Resource Locks
* Tags
* Microsoft Entra ID
* Role-Based Access Control (RBAC)
* Management Groups

### Example I Can Relate To

Imagine a company has many Azure resources:

```text
Development
Testing
Production
```

Governance can help enforce rules such as:

```text
Production resources
        ↓
Must follow company policies
        ↓
Only authorized users can modify them
```

This is particularly important in environments where applications need to follow organizational or regulatory requirements.

### Testing Connection

Governance and compliance are closely related to testing because organizations may need evidence that systems follow required rules.

---

# 8. Manageability

Cloud services can be managed using different tools.

Azure provides tools such as:

* Azure Portal
* Azure CLI
* Azure PowerShell
* Azure Resource Manager
* Azure Advisor

### Azure Portal

A graphical interface for managing Azure resources.

```text
Azure Portal
     ↓
Create / Configure / Monitor
     ↓
Azure Resources
```

### Azure CLI

Command-line tool for managing Azure resources.

### Azure PowerShell

Useful when managing Azure using PowerShell commands and automation.

### Azure Resource Manager

Provides a management layer for creating and managing Azure resources.

### Example I Can Relate To

Because I already have experience with **Azure DevOps and software development**, manageability becomes important when moving from:

```text
Local development
      ↓
Git
      ↓
Azure DevOps
      ↓
Azure
      ↓
Application deployment
```

Cloud management tools help developers and IT teams manage the environment around the application.

---

# 9. Cost Optimization

One major advantage of cloud computing is that organizations do not necessarily need to purchase large amounts of physical infrastructure upfront.

Instead, they can consume resources as required.

### Traditional Approach

```text
Buy servers
     ↓
Install infrastructure
     ↓
Maintain hardware
     ↓
Pay for capacity
```

### Cloud Approach

```text
Choose cloud resources
        ↓
Use resources
        ↓
Monitor usage
        ↓
Pay according to consumption
```

Organizations can also optimize costs by:

* shutting down unnecessary resources;
* selecting appropriate resource sizes;
* monitoring usage;
* using pricing tools;
* removing unused resources.
